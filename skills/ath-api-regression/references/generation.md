# 接口资料到平台原生用例

## 资料与覆盖

主输入是用户明确提供或允许读取的Markdown接口说明，可结合当前需求、API业务用例、项目知识和平台非秘密配置。其他资料能辅助阅读，但不承诺确定性兼容OpenAPI/Postman/cURL导入。已有业务场景可直接承接，不强制先调用另一个用例设计Skill。

记录每份资料的名称、实际可用版本/摘要、定位、可读范围和用途。明确当前需求版本，不把“最新文档”和“已选旧需求版本”无提示合并。未取得正文、仅有链接、上传成功或名称相似，都不足以证明接口细节已知。

对所选范围核对：

- method、服务/环境base URL引用、路径和参数位置；参数必填、类型、边界及业务含义。
- 所需账号用途、认证配置及所选环境绑定。引用现有UUID或列出缺口，不让AI取得秘密明文。
- 多请求的先后依赖、输入变量和响应提取；同一用例内的运行变量不默认为跨用例全局变量。
- 响应状态和业务字段的明确预期、异常分支依据；资料未说明时询问或列缺口，不一律填200。
- 是否产生数据、需要何种清理、清理对象从哪里取得；只读场景可用`cleanup.mode=none`。不为了补齐格式生成宽泛删除。

使用已有平台页面可维护的HTTP请求、结构化提取/断言、受限脚本和受控清理。数据库连接元数据不授予SQL查询；当前正常步骤没有SELECT数据库断言、准备数据INSERT/UPDATE或multipart/binary请求体，超出能力的项保留缺口，不能改成本地执行。

## 生成与检查

先建立可审阅的API场景与用例内容，说明每个请求、变量、断言及清理的依据。按业务链路安排步骤，避免仅为逐接口列清单而丢失关键数据关联，也不强制把所有接口拼成一个长链。

在不发送SUT请求的前提下检查：原生Schema必填字段与枚举；stepId/cleanupStepId唯一；模板引用能否在当时取得；必需提取和实际使用的匹配；断言来源/路径/expected；当前环境用途/连接引用；URL和请求头格式；清理目标与参数绑定。脚本生成应符合平台受限同步JavaScript接口，不能依赖Node、文件系统、网络、npm或`pm.*`。

这些检查能发现静态缺口，不能证明运行成功、业务预期正确或已获批准。无法静态判定的动态脚本变量、实际登录结果、目标可达性等需明确标为未验证；不为消除缺口执行用户代码。

## 写入与交付

遵循用户当前任务已授予的范围。要求“生成并保存”可在范围明确后直接保存待调试草稿；仅要求分析或给建议时先交付草稿，不额外发写请求。普通草稿按原范围保存。真实执行、保存回归资格及修改环境凭据分别按用户的明确任务办理。

用真实父级ID组织测试集、场景和用例；新父级先创建并取得回执，再提交子项。不能将localId、名称或伪造UUID放入正式scenarioId/setId字段。见[原生数据与工具](native-api.md)。

交付本次范围、资料依据、已生成/已保存/仍阻塞的项、实际平台链接，以及静态检查和真实调试的区别。原始JSON需保留完整字段；清单中没有某个用例不代表请求删除它。
